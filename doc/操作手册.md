## 0.1 地点怎么标（示教模式，推荐）

不用记坐标：把车遥控到地方，按一下空格就记成一个航点。

**准备**：只起地图 + 定位 + 导航，先把送物节点关掉

```bash
roslaunch spark_deliver deliver.launch start_deliver:=false
```

等 RViz 起来，确认机器人在地图上的位置跟实际对得上（对不上就先 `2D Pose Estimate` 给一次）。
定位不对就示教，记下来的全是错点。

**示教**：另开一个终端

```bash
rosrun spark_deliver teach_waypoints.py
```

| 键 | 作用 |
|---|---|
| `空格` | 记一个航点，自动命名 航点1、航点2…… |
| `n` | 记一个航点，自己取名（会提示输入，比如「前台」） |
| `h` | 把当前位置设为出发点 |
| `u` | 撤销上一个航点 |
| `l` | 看已记录了哪些 |
| `q` | 退出 |

顺序：`h` 记出发点 → 遥控走到第一个点 → 空格 → 走到第二个点 → 空格 → … → `q` 退出。
每记一个点会响一声，终端上打印这一点的坐标。

退出时它会自动让送物节点重载地点表，**不用重启**。如果送物节点当时没跑
（上面用了 `start_deliver:=false` 就是这样），Ctrl-C 掉终端 1，正常启动一次
`deliver.launch` 就能用了。

> 示教过程中车是你在遥控，导航不会插手，因为没发目标点。

**没有遥控器怎么办**：加 `--teleop`，用键盘开，不用来回切终端

```bash
rosrun spark_deliver teach_waypoints.py --teleop
# w 前进  s 后退  a 左转  d 右转（大写 2 倍速）
# 松手 0.8 秒自动停；空格 = 停车并记点
```

## 0.2 手动改地点表

地点表在 `~/spark_noetic/src/spark_deliver/config/places.yaml`，用 `place_manager.py` 改。
**这个工具不需要开 ROS**，普通终端就能跑。

```bash
# 先看现有哪些点
rosrun spark_deliver place_manager.py list

# 加一个点：x y 从地图上读，朝向用度（0 = 朝 +x，90 = 朝 +y）
rosrun spark_deliver place_manager.py add 前台 --x 1.20 --y 0.50 --yaw 90

# 改坐标：只写要改的字段，其余保持不变
rosrun spark_deliver place_manager.py set 前台 --x 1.35 --yaw 45

# 删一个点：名字或编号都行
rosrun spark_deliver place_manager.py del 前台
rosrun spark_deliver place_manager.py del 2

# 出发点（启动时拿它当 AMCL 初始位姿）
rosrun spark_deliver place_manager.py home --x 0 --y 0 --yaw 0

# 全部清掉，只留出发点
rosrun spark_deliver place_manager.py clear
```

不想记参数就直接跑 `rosrun spark_deliver place_manager.py`，进交互菜单，
`1` 列出 / `2` 新增 / `3` 修改 / `4` 删除 / `5` 出发点 / `6` 清空 / `q` 退出。

写入前会自动备份成 `places.yaml.bak`，改坏了可以拿回来。
改完执行 `rosservice call /spark_deliver/reload "{}"` 让节点重读，或者重启 `deliver.launch`。

## 1. 开机顺序

```bash
cd ~/spark_noetic
source devel/setup.bash
```

**终端 1：起整机**

```bash
roslaunch spark_deliver deliver.launch \
    camera_type:=d435 \
    lidar_type:=ydlidar_g6
```

等 RViz 起来后检查三件事：

1. 地图出来了，激光点跟地图上的墙对得上
2. 机器人模型在地图上的位置跟实际位置一致（不一致就手动 `2D Pose Estimate`）
3. 状态话题有输出：`rostopic echo -n1 /spark_deliver/status`

**终端 2：操作面板**

```bash
rosrun spark_deliver cmd_panel.py
```

## 2. 演示脚本（约 3 分钟）

**开场（20 秒）**

> “这是一个送物小车。把东西放上去，选一个地点，它自己送过去，到了会说话提示，  
> 顺便拍一张照片留档，没人取就自己回来。”

**第 1 步：把水瓶放到机器人平台上，面板按 `1`（送到前台）**

看点：

- 车动了，RViz 里能看到全局路径和局部代价地图
- 到点后**自己停下来**，并说“前台，东西送到了，请取走”

**第 2 步：过去把东西拿走，按 `c` 确认**

看点：

- 立刻回一句“好的，我回去了”，然后自己开回出发点
- 如果不动手，等 60 秒它也会自己回去（可以说：“超时也会自己回来，不会一直杵在那”）

**第 3 步：提一句拍照留档**

```bash
xdg-open ~/.spark_deliver/photos/index.html
```

> “每次到点都拍了一张，按时间排好，地点、时间都在上面。这就是送达记录。”

**第 4 步（可选，10 秒）：巡拍模式**

```bash
# 另开终端
roslaunch spark_deliver photo_round.launch
```

> “同一个包还有巡拍模式，按地点表走一圈每个点拍一张，可以当环境记录用。”

**收尾（10 秒）**

> “整个包只新增文件，导航、定位、相机驱动都是调用现成的，没动别人一行代码。”

## 4. 排障速查

| 现象                    | 先看什么                                  | 处理                             |
| --------------------- | ------------------------------------- | ------------------------------ |
| 车不动，状态一直 `navigating` | `rostopic echo /move_base/status`     | 没 ACTIVE 说明 move_base 没起或目标不可达 |
| 一动就撞/走歪               | RViz 里激光和地图是否重合                       | 重新给一次 `2D Pose Estimate`       |
| 到点不拍照                 | `rostopic hz /camera/color/image_raw` | 话题没数据 → 相机型号参数填错               |
| 没声音                   | `which ekho`                          | 没装就 `start_tts:=false`，改用面板看状态 |
| 面板按了没反应               | `rostopic echo /spark_deliver/status` | 服务/话题没通，检查 deliver 节点是否在跑      |
| 报“没有找到地点”             | `place_manager.py list`               | 地点名输入错了，或者有空格                  |
| 面板里一个地点都没有            | `place_manager.py list`               | 还没标点，用 `add` 加一个                 |
| 一直说“正在忙”              | 状态是不是 `waiting`                       | 上一单还没确认，按 `c` 或 `x`            |

**急停**：面板按 `x`，或

```bash
rosservice call /spark_deliver/cancel "{}"
```

还不行就直接把机器人电源关掉——底盘失电即停。

## 5. 安全注意

- 第一次跑把 `wait_pickup_timeout` 设小一点（比如 15），确认逻辑对了再放大
- 演示场地地面别有散落的线缆，雷达扫不到细线
- 人站的位置别贴着目标点，move_base 会把它当成障碍一直规划失败
- 东西别放太高，重心偏了转弯会掉
